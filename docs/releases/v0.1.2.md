# Plugin Runtime 0.1.2

Runtime and chart 0.1.2 add optional authenticated HTTPS delivery of a
plugin-only `plugin.tar` from a Generic Package Registry. The tar carries the
original OCI package, signature, SBOM and provenance bytes. Operators pin its
SHA256 and the original package/evidence identities from an independently
approved release record. No new outer signature or OCI wrapper is introduced.

Select `package.transport=https` with the approved URL, archive/package/manifest
pins and referrer digests. Supply the independent publisher bootstrap and a
single-host dockerconfigjson Secret containing Basic deploy-token credentials.
GitLab Generic Package readers need `read_package_registry`; OCI readers still
use `read_registry`. Keep customer delivery projects stable-only and prohibit
duplicate/overwrite publication. The archive digest and publisher signatures
remain the install identity even when registry administrators can mutate files.

The chart's scratch runtime requires `package.registryCASecret` with independent
public TLS roots for GitLab and its object store. HTTPS and certificate checks
remain mandatory. One redirect to an exact `package.https.redirectHosts` entry
is allowed, with all original headers removed, including on a same-host hop.
Further redirects, unknown hosts, HTTP, credential-bearing URLs and initial URL
queries fail closed. Signed object-store queries are accepted only on the
approved redirect.

The runtime downloads to owned temporary storage, checks the approved archive
hash before extraction and admits only a bounded exact OCI closure. Links,
foreign files/blobs, duplicate or unsafe paths, incomplete archives and excess
sizes are refused. The archive cap is 634,126,336 bytes (604.75 MiB), following
the existing full package limits plus evidence and tar overhead. HTTPS Pods
allow 1280 MiB of temporary disk for the archive and extracted layout, in
addition to the existing package volume. Check ephemeral-storage capacity before
switching transports. OCI Pods retain the 16 MiB temporary limit.

Both runtime and migration retain the independent publisher gate, Cosign
verification of each configured evidence part and normal package validation
before execution. Existing installed-digest key-window behavior and revocation
checks remain. Fetch credentials and TLS CA files reach only the fetch init
container. Default `package.transport=oci` preserves the original ten-stage
signed OCI init chain. The plugin protocol, manifest schema and signed layer
media types are unchanged; existing packages remain compatible.

Upgrade the digest-pinned runtime image and chart together before enabling
HTTPS. Runtime 0.1.1 and earlier do not implement `fetch-https` and cannot consume
this delivery route. Retain the former OCI reference and verification inputs if
you need to return to the OCI transport. A Helm rollback does not roll back
plugin data, restore a package registry or revoke already downloaded packages.

Official builds retain Go 1.26.10, ORAS 1.3.4 and Cosign 3.1.3 pins and normal
source/artifact, provenance, SPDX, signature and publication gates. HTTPS
fetching uses the Go standard library; no application dependency or additional
fetch helper image is added. The historical
[0.1.1 third-party disposition](vendor-disposition-v0.1.1.md) is scoped to that
release and does not establish a new security acceptance for 0.1.2. This release
contains the generic runtime, native archives and Helm chart; commercial plugin
source, signed packages, publisher keys and licences are delivered separately.

See [HTTPS delivery](../https-delivery.md) for the complete operator values and
archive contract.
